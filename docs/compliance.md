# Сверка с ТЗ

Основание: приложенное `DELO_Codex_TZ.md` версии 2.0. Проверка проведена 30.09.2026 по исходникам и выполненным тестам из [отчёта](test-report.md). Статус «реализовано» означает наличие функции и локальной проверки; внешняя интеграция выделена отдельно.

| Раздел ТЗ | Статус | Проверяемый результат и граница |
|---|---|---|
| 1. Основной путь и P0 | Частично | Бот, Mini App, профиль, каталог, план, напоминания и возврат по deep link реализованы. Сквозной путь локально пройден; реальный MAX ещё не проверен. P1 не добавлялся. |
| 2. Стек и проект | Реализовано | React/TypeScript strict/Vite/Router/Query, CSS Modules, FastAPI/Pydantic/SQLAlchemy/Alembic, PostgreSQL 16 в Compose, отдельный worker, lock-файлы. Структура модулей компактнее примерной структуры в ТЗ. |
| 3. Телефон и компьютер | Частично | Проверены viewport 360, 390, 480, 768, 1366, 1920px, маршруты, фильтры, resize и отсутствие горизонтальной прокрутки плана. Реальные MAX-клиенты, экранная клавиатура и 200% zoom не проверены вручную. |
| 4. Визуальный язык и состояния | Частично | Токены цветов, CSS Modules, адаптивная навигация, skeleton/empty/error/offline, повтор, диалог с Escape и возвратом фокуса. Отдельный инструментальный аудит контраста и всей клавиатурной навигации не проводился. |
| 5. Экраны и данные | Реализовано локально | Профиль, главная, поиск/фильтры, детали, план, чек-лист, сроки, статус уведомлений и специальное уточнение условий работают. Данные учебные. |
| 6. Правила подбора | Реализовано | `eq/in/gte/lte/exists`, группы `all/any`, `unknown/not_applicable`, срок и свежесть источника, детерминированный порядок статусов и сортировка; процент пригодности удалён. Тесты покрывают граничные случаи. |
| 7. Модель и seed | Частично | Миграция, 8 синтетических программ, демопрофиль, проверка формата до импорта, идемпотентный seed. Отдельной команды `reset-demo` нет; осознанная очистка demo volume описана в README. PostgreSQL и рестарт volume не испытаны из-за отсутствия Docker. |
| 8. API и согласованность | Частично | Маршруты ТЗ, OpenAPI, изоляция, атомарная проверка версий, Idempotency-Key, транзакция plan/items/outbox и уникальный активный план. `DATA-API.yaml` остаётся черновиком до схемы организаторов; HTTPS endpoint не предоставлен. |
| 9. MAX | Частично | Bridge adapter, серверная проверка подписи/срока initData, сессии, webhook secret/дедупликация, mock и real API adapter, команды бота и deep link. Нет токена, бота, привязки Mini App и публичного HTTPS URL для реальной проверки. |
| 10. Напоминания | Частично | Worker, транзакционное взятие, lease, retry, `uncertain`, лимит тестового напоминания и `simulated` в mock. Реальная доставка MAX и восстановление очереди после рестарта PostgreSQL не проверены. |
| 11. AI | По плану P0 | Не включён: в ТЗ это P1 после готового P0. |
| 12. Безопасность | Частично | Изоляция пользователей, ограничение размера запроса, rate limit, dev-auth запрещён в production, секреты из env, HTTPS-проверка конфигурации, без сканов/заявок. Формальный production-аудит и операционная процедура удаления данных не проведены. |
| 13. Запуск | Частично | Compose, Dockerfiles, nginx, `.env.example`, README и команды подготовлены. Docker на машине отсутствует, поэтому чистую сборку и время до 5 минут подтвердить нельзя. |
| 14. Проверки и gate | Частично | 14 pytest, 1 Vitest, сборка и 4 Playwright пройдены. Gate требует чистый Docker, реальное сообщение MAX и проверку двух MAX-клиентов; они открыты. |
| 15. Пакет сдачи | Частично | Исходники, миграция, seed, OpenAPI, DATA-API, документация и тестовый отчёт есть в локальном commit. Нет публичных ссылок, опубликованной ветки и закрытой PDF-презентации. Официальный PDF кейса для сверки не предоставлен. |

Чтобы закрыть gate, нужны Docker на машине проверки, доступ к зарегистрированному боту/MAX Mini App, публичный HTTPS-домен, официальные данные программ и PDF/схема организаторов. Секреты следует внести в закрытое окружение, а не в Git или переписку.
